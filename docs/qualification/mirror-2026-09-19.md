## Storage and schema boundary

Keep the existing `Anchor.store` URL, all thirteen SwiftData model types,
UUIDs, relationships and native CloudKit container
`iCloud.com.significanthobbies.anchor`. Restore `.private(cloudKitIdentifier)`
for persistent stores on Mac, iPhone and Watch; `.localOnly` remains `.none`.
Do not create a new CloudKit zone or replace native mirroring in this repair.
The optional Hub runtime has only the Hub transport.

| Existing representation | Proposed repaired representation | Rule |
| --- | --- | --- |
| Native SwiftData/CloudKit model records | Same schema and native mirror | No re-key, destructive migration or remote-record rewrite |
| `FocusSession.hubAccountID` | Same optional ownership field | Existing nonempty ownership is preserved |
| Local `Distraction.note` / `keywords` legacy fields | Same fields, emptied after verified vault copy | Never remove schema fields or repopulate them from Hub |
| `Anchor.store.private-notes/<UUID>.json` | Same local vault and UUID | Never include in Hub, CloudKit payloads or bookkeeping |
| Legacy Hub summary named bare UUID | Same local session UUID and original raw Hub wire alias | Preserve transport alias/version evidence |
| Canonical Hub focus-session payload | Account-scoped session projection | Trusted account validates ownership; payload does not grant it |
| Canonical Hub distraction payload | Metadata linked to an eligible session | No note or keywords; no orphan/foreign parent |
| Other eleven canonical model kinds | Native/iCloud only for this repair | No per-record Hub provenance exists yet |

This intentionally narrows the Hub surface. A history approval is not implicit
approval to export every goal, project, preference, plan, behavior or divergence
record. Full-document Hub sync needs a separate ownership/consent contract.
The Google Calendar work remains outside this repair.

## Startup and fallback

1. Resolve the existing store URL and explicit local-only/demo policy.
2. Before opening a native mirrored container, open that same store locally.
   Write, synchronize and read-verify each legacy private-note copy; preserve
   conflicting versions in the vault; clear legacy fields and save metadata.
3. Only successful preflight permits the persistent native CloudKit open.
   A note-migration failure reopens the same existing store locally and exposes
   the storage warning. Never substitute an empty memory store for that failure.
4. Compose optional Hub sync using the actual returned store kind and external
   sync policy. Local-only, in-memory, demo, explicit-path and failed-preflight
   startup must not create an enabled account/cloud runtime or inspect tokens.
5. Watch retains its existing native remote workflow and does not require a Hub
   account. Do not solve this by retaining legacy CloudKit on Watch alone while
   moving phone/Mac to another zone.

An unrelated persistent-open failure must preserve the files and report the
actual fallback kind. This repair must not add deletion, store replacement or
bookkeeping reset as recovery. Existing generic memory fallback behavior is
not proof that an existing unreadable store was recovered.

## Hub ownership projection and inbound trust

Each pass captures a freshly verified account and validates that same account
through application/acknowledgement boundaries. Device history approval gates
Hub access; it does not replace per-record checks.

- Export sessions only when `hubAccountID` equals the verified account ID.
  Approval may claim nil-owned local sessions under the existing no-active-
  session rule, but may never adopt another account's sessions.
- Export distraction metadata only when its parent is in that eligible session
  set. Nil/foreign/orphan parents are ineligible. Use this identical projection
  for pending counts and for transport eligibility.
- Omission from an account projection is not deletion. Generate distraction
  tombstones only from durable evidence that the name belonged to this account
  and was actually deleted. A broad old ledger is insufficient evidence.
  Never tombstone foreign, unowned or newly excluded model kinds. Preserve
  session history; do not apply Hub session tombstones.
- On Hub download, validate record kind, canonical name UUID, payload UUID and
  parent references before changing a model. A supplied `hubAccountID` is
  untrusted: reject a foreign nonempty value. Stamp genuinely new nil-owned or
  legacy imports with the verified Hub account. A collision with an existing
  nil-owned local session requires local adoption approval; do not silently
  claim it from a download. A foreign-owned local UUID is always rejected.
- Reject a distraction that would attach to a foreign/nil-owned session or
  reassign an existing foreign-owned association. Validate the whole batch
  before any mutation, including parents arriving later in that batch.
- Unsupported prior full-document records must not mutate the native planner.
  Treat them as deliberately outside this projection; do not fabricate local
  deletion or canonical ownership to consume them. Record the disposition
  without persisting private payloads in diagnostic output.

With Hub as the only runtime transport, filtering the snapshot is sufficient
provided the ledger/deletion rules also hold. If a second transport returns,
use transport-specific eligibility: native Apple continuity must continue to
include local records regardless of their Hub owner.

## Durable application

Decode and validate the entire batch first. Apply scalar fields and resolved
relationships in a fresh `ModelContext` belonging to the existing container,
with autosave disabled. The sync callback succeeds only after `save()` returns
success, or after that fresh context proves the batch is already durable.
Discard/rollback the isolated context on decode, ownership or save failure;
leave unrelated unsaved UI edits alone. Do not use equality against a previously
failed main-context mutation as proof of durable application.

Local export represents committed state. The implemented repair defers the pass
while the main context has pending edits; it never silently saves a user draft. Refresh the
UI/controller after a successful isolated commit so active session state follows
the saved store. Perform a fresh main-context fetch of affected entities before
reconciling the controller; do not assume its already-held model references have
refreshed. Do not reset or roll back the main context. Private-note cleanup
follows successful metadata deletion and cannot make a failed metadata save look
successful.

## Legacy naming and mixed-client behavior

Recognize genuine legacy summaries with bare UUID names before canonical kind
dispatch. Map a bare UUID and its `session-` canonical name to the same local
UUID. Preserve canonical session details when an older summary collides; do
not downgrade a running/richer record to a finished summary. New legacy-only
imports are finished records owned by the verified Hub account.

Name normalization must preserve the original Hub record ID and version used
for cursor/version bookkeeping. Retain alias evidence so repeated pulls,
restarts and later canonical writes do not create a second local session,
lose the old version, manufacture a legacy tombstone, or repeatedly echo an
unchanged import. Do not delete old Hub records as a shortcut to normalization.
Any compatibility for non-UUID historic fixture names needs an explicit stable
mapping; arbitrary foreign names are not valid sessions merely because their
JSON resembles a summary.

A minimal implementation can retain the same `SyncVersionStore` actor used by
Hub transport instead of adding a SwiftData alias field. After a successful
pull, choose an existing positive-version lowercase bare UUID first, uppercase
bare UUID second, otherwise the canonical name. Version keys are exact and
case-sensitive; their values are independent per alias, not comparable clocks.
Hub pull durably writes them before application, so a later mirror-ledger save
failure does not erase the selected raw alias. Keep payload identity and source
timestamps unchanged by name selection, and recognize raw UUID names carrying
either legacy or canonical session payloads as append-only sessions.

This lookup is valid only behind the verified account/ownership gate: the
version store itself has no account dimension. A progressed mirror ledger with
missing or unreadable version state must fail closed for scoped recovery/full
repull; zero lookup is not proof that an old remote alias never existed. Already
coexisting aliases remain a separate remote-duplicate limitation and are not
deleted by this repair.

Deferring while the main context has changes must throw from snapshot/apply,
not return a successful no-op. Recheck after asynchronous account/version work.
Also capture the main-context save generation with the snapshot and compare it
immediately before synchronous isolated application: an intervening *saved*
local edit no longer sets `hasChanges` but still invalidates the earlier merge.

Old native clients continue to use the same store/cloud schema. A watch-created
session may have nil Hub ownership and remains native/iCloud-only until explicit
adoption. Late old-device note values are copied into the local vault without
overwriting a newer local edit. The existing remote-change callback runs that
migration; if it fails, it currently reports an error without disabling an
already-running native CloudKit mirror. This is an explicit live privacy and
mixed-client acceptance blocker, not a proven cloud pause.

## Rollback and recovery

Before any future installation, establish a recoverable consistent copy of the
store and adjacent private-note vault under separately authorized local handling.
A database file without its vault cannot recover private notes. Never overwrite
owner data with a synthetic test fixture.

A source rollback may disable the new Hub leg while native CloudKit remains on
the existing schema. Preserve all ownership, legacy aliases, cursors, versions,
pending changes and note files. Do not clear bookkeeping to make sync appear
healthy; replay can republish foreign data. If unsafe full-document state was
already written, retain it for scoped diagnosis and block uncertain exports.
Remote removal or account-data repair requires a separately reviewed action.

Do not downgrade to code predating the private-note accessors: its empty legacy
fields do not mean the user's vault notes disappeared. Do not roll back by
copying private notes into mirrored fields. On space/permission failures, repair
the local storage condition and retry the retained operation against the same
store; on ownership conflicts, reconnect the correct account or seek explicit
adoption, never rewrite a foreign owner.

## Required evidence before acceptance

Source regressions must establish mixed A/B/nil ownership, distraction parent
checks, no deletion from filtering, forged inbound ownership, UUID mismatch,
real read-only-store save failure and retry, valid-then-malformed batch rollback,
isolated-context UI preservation, bare UUID import/alias restart behavior,
pending-count parity, and startup transport gating. Existing note migration
fixtures must still preserve IDs, relationships, timing and local content.
All assertions and dependency revisions must be recorded against the final head.

Signed physical Mac/iPhone/Watch continuity remains unqualified: start, pause,
resume and capture across already-open devices; offline recovery; existing
cloud-only history restoration; exact deployed schema; and old/new client
coexistence require firsthand evidence. Live late-import note failure and
historical queued CloudKit export behavior remain privacy blockers. Synthetic
field injection and simulator compilation cannot close either gate.
